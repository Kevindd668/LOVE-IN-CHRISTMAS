## 5. 中央纯黑方块闪烁修复记录

**现象：** 实际使用中，页面中央偶发出现一个纯黑矩形，闪烁；截图里它覆盖场景，甚至贴近标题和照片边框。

**定位依据：**

- 从 2560 × 1368 截图提取出黑块边界约为 `x=658…1742 / y=295…1361`，颜色为 `rgb(0,0,0)`；四边完全水平/垂直，没有透视、圆角或照片相框结构。
- 项目 DOM 中没有任何宽高在此量级、背景为纯黑、且拥有对应 z-index 的浮层；照片卡片最大尺寸和全屏弹窗的尺寸都对不上。
- Three.js 场景中也没有会以屏幕轴对齐正方形形式出现的纯黑材质。因此它不是树、礼物、照片卡片、520 / 1314 或粒子模型，而是 **Edge/Chromium 在 Windows 上的合成层掉块/闪块**（accelerated WebGL 与透明/毛玻璃/混合层叠加时的 GPU compositing 异常），也可能被 MPO、屏幕叠加层或显卡驱动放大。

**已修复 / 加固：**

1. 移除了全屏 `mix-blend-mode: soft-light` 的动态胶片颗粒层，改为静态、无混合的轻颗粒。
2. 隐藏状态的面板、照片灯箱、愿望弹窗、遮罩、Toast 不再保留 `backdrop-filter`；毛玻璃只在控制面板打开时启用。
3. 将 WebGL 画布提升到独立的稳定合成层。
4. 关闭默认 framebuffer 上无用的额外 MSAA；场景仍由离屏 MSAA / Bloom 管线处理。
5. 增加了 WebGL context restored 后重建后处理管线的恢复逻辑，以及从隐藏状态返回时的强制 resize/重绘。
6. 增加了照片卡片近镜头时的屏占比上限，防止任何照片卡片异常放大挡住镜头。
7. 增加**兼容渲染模式**：跳过 Bloom 离屏合成、直接渲染到画布，并关闭剩余毛玻璃与全屏渐变/颗粒层，用于隔离浏览器合成问题。该模式现已设为**默认**，`?safe=1` 保持兼容。
8. 完整 Bloom + 毛玻璃模式仍保留，可通过 `?full=1`（或 `?safe=0`）开启。

**验证：** 最终离线文件在 2560 宽度下以默认兼容模式与 `?full=1` 打开，均正常启动，无 console/page error；默认模式 240 FPS；兼容模式直接渲染到画布，面板关闭时计算样式中的 `backdrop-filter` 为 `none`。由于原异常依赖机器/浏览器合成状态，无法仅靠页面代码复现，因此同时保留了上述硬件/MPO 排查步骤。

> 若兼容模式仍出现相同黑块：在 Edge 中临时关闭“使用图形加速”后重启，或关闭 RTSS / Game Bar / QQ 等覆盖层；若黑块消失，则为系统级 GPU 叠加层问题，而不是圣诞礼物页面内的模型。

## 6. 已知边界

1. **照片只存在于当前标签页。** 这是需求“本地处理、不上传服务器”的直接结果；刷新页面会回到内置示例照片。
2. **内置照片为程序化冬夜海报**，用于展示相框和轨道效果；上传你们的真实照片后，场景会立刻变成个人版本。
3. **照片在 24 张时会变成高密度照片墙。** 功能与性能正常，但轨道会出现层叠；这是“最多 24 张”的预期视觉行为。
4. **音乐是 Web Audio 运行时合成。** 它是原创氛围旋律，不是某首外部歌曲；切换曲目会有短暂的重新编排。
5. **音频需要一次用户手势。** 直接打开页面时不会自动播放；点击音乐、开始演示或浪漫模式后才会开始。
6. **浏览器范围。** 已实测 Chromium 内核的 Edge；没有把 Safari / iOS 作为验收目标。移动端布局在 Chromium 响应式视口下验证，未做实体 iPhone 兼容测试。
7. **程序化美术是写意风格。** 优先保证“完整、温柔、可互动、可定制”，而不是照片级植物扫描。
